# ProxyDog

**当前版本 v1.8.3** · 作者 [Deep-webs](https://github.com/Deep-webs) ·
开源地址 <https://github.com/Deep-webs/ProxyDog> · License: MIT

一个开箱即用的单机代理池：自动抓取免费节点 → 真实验证 → 按策略轮换出口，
对外用一个端口同时提供 HTTP 与 SOCKS5 代理，带面板做日常管理。
Python + Flask + aiohttp + SQLite，无前端构建，双击 `start-proxydog.bat` 即用。

```
代理端口  http://127.0.0.1:2080   （HTTP）
SOCKS5   socks5://127.0.0.1:2081 （独立端口；设置里开「共用一个端口」则只留 2080，两种协议都能连）
面板      http://127.0.0.1:5002   （本机打开即用）
健康探活  http://127.0.0.1:5002/api/health   （免认证，给监控/守护脚本用）
```

端口模式在「设置 → 代理监听」用一颗开关切换：**开启 = 只监听一个端口（2080，HTTP/SOCKS5 自动识别）；
关闭 = 两个端口（HTTP 2080 + SOCKS5 2081）**。切换即时生效，不用重启。

## 面板密码（默认不启用）

本机自用时打开面板就是全部权限，不用输密码。

- 未启用面板密码时只允许**本机**访问面板；想让局域网其他机器用，请配置 IP 白名单（维护 → 打开设置）；
- 如果面板要暴露到非本机网络，建议开启「设置 → 面板访问与日志 → 面板登录保护」：首次启动自动创建账号 **admin**，随机密码写入 `data/first-login.txt`（登录改完密码后请删除该文件）；
- 忘记密码：项目目录执行 `python app.py --reset-password`，控制台会打印新密码；
- 同一 IP 连续失败 5 次锁定 10 分钟（可在设置里调）；
- 会话密钥持久化在 `data/secret.key`，重启不会把登录状态全部踢掉。

## 给程序调用的取用接口

面板之外，ProxyDog 也是一个代理池服务，用 `X-API-Key` 认证（在「维护 → API Key」生成）：

```bash
KEY="pd-xxxx"
curl "http://127.0.0.1:5002/api/pool/get?count=5"                    -H "X-API-Key: $KEY"   # 纯文本，每行一条
curl "http://127.0.0.1:5002/api/pool/get?count=5&protocol=http&format=json" -H "X-API-Key: $KEY"
curl "http://127.0.0.1:5002/api/pool/count"                          -H "X-API-Key: $KEY"
curl "http://127.0.0.1:5002/api/pool/get" -H "X-API-Key: $KEY"   # 无可用出口时返回 404
```

支持的参数：`count`（1~200）、`protocol`（http/https/socks5）、`max_delay`（毫秒，
不传时默认用面板设置的延迟上限）、`region`（模糊匹配）、`format`（text/json）。
`/sub/<token>` 订阅同样默认按面板的延迟上限过滤，可用 `max_delay` 传更严的值。

## 设计取舍

| 关心的问题 | 这里的做法 |
|---|---|
| 面板/代理监听范围 | 默认只监听 `127.0.0.1`，需要局域网访问再改监听地址 + IP 白名单 |
| 入站认证 | 「设置 → 入站认证」里维护**代理账号表**（可多个，各自密码/备注/启停/使用统计）；账号表非空时 HTTP 回 407、SOCKS5 按 RFC 1928 回 `05 02`，任一启用账号匹配即放行；表为空则直接放行，不存在"HTTP 能用 SOCKS5 不能用" |
| 超时预算 | 拨号超时与整体重试预算分离，慢出口不会吃光重试时间 |
| 单条维护 | 表格里每条都有启用开关，可编辑 host / port / 协议 / 账号 |
| 订阅兼容 | 纯文本、base64、Clash YAML、JSON 数组都能导入，也能按这些格式输出订阅 |
| 出口可观测 | 「最近请求」逐条显示目标、出口、结果、耗时；概览显示当前出口与轮换进度 |
| SQLite 稳定性 | `wal_autocheckpoint=256`，每小时主动 TRUNCATE，支持在线备份 |

## 快速开始

1. 双击 `start-proxydog.bat`（会自动找 Python、缺依赖则装）。
2. 打开 <http://127.0.0.1:5002>。
3. 点「自动抓取」拉一批免费代理，或「手动添加 / 导入订阅」。
4. 浏览器或工具里把代理填成 `127.0.0.1:2080`（HTTP）或 `127.0.0.1:2081`（SOCKS5）；
   如果开了「共用一个端口」，两种协议都填 `127.0.0.1:2080`。

命令行启动：

```bash
python app.py
```

Docker 一键部署（v1.6，照 ProxyCat 的容器用法）：

```bash
docker compose up -d --build
```

容器里默认以非 root 运行，`data/`（代理库与设置）和 `logs/` 已挂载到宿主机；
监听地址用环境变量 `PROXYDOG_LISTEN_HOST` / `PROXYDOG_WEB_HOST` 覆盖成 `0.0.0.0`，
面板端口 5002、HTTP 2080、SOCKS5 2081。首次登录账号 `admin`，密码在 `data/first-login.txt`。

### 接入空间测绘 + 内容校验（v1.8.3）

这版对着「无影为什么比我们稳」逐条对齐，修的都是会直接让功能失效的 bug：

- **Quake 打码 IP 还原**：普通账号返回的 `ip` 是 `14.*.*.*`，但 `id` 字段是
  `14.29.228.23_1024_tcp`，真地址就在里面。以前把打码地址直接丢掉，等于一条都没抓到。
- **Quake 限流与深度上限**：`code` 是字符串（`q3005` 限流 / `q2001` 翻页到底），
  旧代码直接 `int(code)` 会崩；现在退避重试，并把「最多翻到第 1000 条」当正常收尾。
- **只抓「免认证」的 SOCKS5**：握手响应写着 `Auth Method: 0x2 (Username/Password)`
  的节点永远用不了，抓的时候就丢掉，不再白占验证名额。
- **Hunter 接口修好**：域名是 `hunter.qianxin.com`（旧代码写成 `.net`，DNS 都解析不了），
  `search` 参数必须是 `base64(urlencode(语法))`，少一层就永远「参数错误」。
- **单源抓取只抓那个源**：`skip_builtin` 之前没生效，点一次「抓取」会顺带跑几十个
  内置清单，把统计冲掉；现在只跑选中的测绘源。
- **单源抓取能真的拿到 key**：以前把给前端看的脱敏配置（`creds_masked`）传给抓取函数，
  永远报「缺少 xxx key」。
- **验证必须过内容校验**：默认按验证目标自动取特征串（baidu → 「百度一下」）。
  实测同一批节点只看 200 能过 73%，加内容校验只剩 33%——差的 40% 全是劫持页/假 200。
- **死端口黑名单**：样本 ≥80 次且一次都没成功过的端口（6363 / 49667 / 9444 这类批量
  部署的假代理）直接跳过，同样的验证时间能多筛一倍真节点。
- **死条目自动清理**：从没成功过的节点保留 4 小时后删除（`设置 → 验证 → 死条目自动清理`），
  库不再涨到上万条死数据。

### 向「刚验证过」要质量（v1.8.2）

实测了公开源的头 60 条：用 baidu 验证，通过率只有 1%~3%，中位延迟 2.3~5.2 秒——
免费池的问题不是「抓得少」，而是「节点死得快」。所以这版围绕**新鲜度**收紧：

- **5 分钟重验证 + 轮转取样**：默认周期 300 秒（原 10 分钟）。以前每轮都按延迟升序取前
  600 条，等于反复验最快的那几条，慢的、放久的永远排不上队；现在按 `last_check` 升序
  取，全池都能轮到，池子里不再攒「看起来有效、其实早死了」的节点。
- **轻量重验证**：定期重验只测「通不通、多快」，不再每条都补一次匿名/HTTPS 探测
  （那两项入库时已经采过），单条从 2~3 个请求降到 1 个；验证并发默认 160、超时 5 秒，
  吞吐约 5.6 条/秒，600 条约 2 分钟一轮。
- **智能预检新鲜期 60 秒**：一分钟内拨通过的出口免检直接放行，超过就先拨一次、
  不通当场换下一条并隔离 3 分钟——不会把「第一次失败」甩给使用者。
- **拨号超时 5 秒**（原 8 秒）：坏出口最多拖 5 秒就换，3 次重试也不会卡十几秒。
- **延迟上限 2 秒 / 健康分下限 20**：3 秒才通的节点实际体验就是「卡」，直接退出轮换。
- **失败占比阈值 50%**（原 60%）：窗口内一半以上失败就下场，而不是等连续失败 4 次。
- **新增 5 个公开源**（TheSpeedX / monosans / clarketm），单次抓取多约 4400 条候选，
  配合严格验证筛出更多好节点。

### 出口质量三件套（v1.8.1）

免费代理天生参差，池子大不等于好用。这版把「坏节点赖着不走」的几条路都堵上：

- **升级式隔离**：连续失败超过隔离线后，每多失败一次冷却时长翻倍
  （10min → 20min → 40min → … 上限 24h）。以前坏节点关 10 分钟就准时复活，
  一直占着轮换额度；现在惯犯基本退场，临时抖动的节点复活一次就回池。
- **重验证提速**：后台自动重验证从写死的 30 分钟一次改成默认 **10 分钟**
  （设置 → 调度 → 自动重验证周期，可调 120s 起），每轮覆盖 600 条；
  坏掉的出口最迟 10 分钟内被踢出候选。
- **低分节点几乎选不中**：健康分权重乘数加强（90 分 ≈ ×1.95、30 分 ≈ ×0.75、
  0 分 ≈ ×0.15），流量持续集中到又快又稳的少数节点上。
- 顺手修掉池表「全选」只勾中第一行的问题（行内启用开关也是 checkbox，
  遍历时取不到 `onclick` 抛异常中断了循环）。

## 出口增强与网络协议（v1.7）

### 池空不「死」：可用性保障链

代理在跑、池子却没节点时，按下面四层兜底，尽量不中断服务：

1. **池空自愈**：先把最久没验过的一小批失效出口临时捞回来顶着（普通模式 12 条，
   无限模式全量），请求撞上死出口会自动换下一条；同时在后台重验证这批出口。
2. **即时补货**：池空的第一时间直接触发抓取（不等 60 秒巡检、冷却压到 20 秒），
   抓来的新出口**分块验证、验完一块立刻入库可用**，不用等整批跑完。
3. **定时自检**：每 60 秒检查有效数是否低于「扩容阈值」；每 10 分钟（可配）把有效池
   重验一遍，同时轮验失效队列，救活能复活的（以前判死就永久出局）。
4. **上限不再卡死**：池内上限按「有效出口数」算而不是总数——池内堆满死节点时
   总数早就到顶，按总数卡就永远补不进来。

实测（沙箱，池内 117 条全部判死）：t+16s 恢复到 9~12 条临时候选，t+56s 首个
请求 200，之后稳定 200；补货任务「候选 120，新增 118，补后可用 11」。
注意：彻底空池后的头 ~1 分钟内仍可能有请求 502——源抓取 + 验证需要时间，
任何工具都无法凭空变出活节点，但池子会自动爬回来。

### 出口健康分 + 自动扩容

- **健康分 0~100** = 成功率(50) + 延迟(25) + 连续成功(10) + 匿名度(10) + HTTPS(5)，
  每 60 秒按最近 N 条访问记录重算（`health_window`，默认 200），直接当轮换权重乘数；
  还能设「健康分下限」，低于线的出口不参与轮换。
- **自动扩容**：有效出口低于 `scale_min`（默认 15）时自动抓一批补货（`scale_batch` 条），
  带冷却时间与池内上限；也可以在任务中心点「立即补货」手动触发。

### 出口带宽测速

- 池页每行「测速」按钮：通过该出口从测速地址（默认 Cloudflare 2MB）下载并算真实 KB/s；
- 「批量测速」对池内前 20 条跑一遍，结果落在「速率」列与 `speed` 字段。

### 数据中心 IP / 住宅 IP 标记

- 离线库（`ipclass.py` 内置 137 个云厂商网段 + 68 组关键词）先判；
  判不出再联网查 ASN/ISP（ipinfo.io → ip.sb → ip-api 依次兜底），结果落盘缓存 7 天；
- 池页「出口 IP」列直接挂「机房 / 住宅」徽标；住宅 IP 天然比机房 IP 更接近真实用户，
  挑出口做风控敏感业务时按这个标记筛。

### DNS 解析策略（DNS over SOCKS）

`dns_mode` 三档：`remote`（默认，域名交给上游解析，本机零泄漏）/ `proxy`（在代理隧道里
向指定 DNS 发 TCP 查询，本机不发明文 DNS 也不依赖上游解析器）/ `local`（本地解析，兼容老上游）。

### 入站 SOCKS4 / SOCKS4a 与多跳上游链

- 同一端口自动识别 SOCKS5 / SOCKS4 / SOCKS4a（4a 允许客户端传域名），可用开关关闭；
- **proxy chain**：池里的出口当第一跳，再按 `chain_hops` 依次串 SOCKS5 节点
  （`socks5://user:pass@1.2.3.4:1080,socks5://5.6.7.8:1080`，最多 5 跳），最后才到目标。

### 抓取插件目录 + 热重载

把 `.py` 丢进 `plugins/` 就多一个抓取源，保存文件 2 秒内自动重载（语法错误时保留上一份
能跑的版本并在任务中心标红）。插件只需提供 `URLS = [...]` 静态清单或 `def fetch(): ...`
自行抓取，可选 `NAME / PROTOCOL / ENABLED / DESC / check()`。目录里自带两个示例。
⚠️ 插件跑在本进程内，等同本机代码执行权限，面板不提供上传入口。

### 任务中心

侧边栏新增「任务中心」（快捷键 8）：抓取、验证、测速、IP 判定、扩容的进度、日志、
耗时、失败原因统一在这看，运行中的任务数还会显示在导航徽标上；支持取消与类型筛选。

### 明暗主题 + 中英双语

- 顶栏 ☾/☀ 或快捷键 `T` 切换主题，`L` 切换中/英，选择存 localStorage 并同步到服务端设置；
- 浅色主题覆盖全部面板（侧栏、表格、弹窗、告警、图表）。

## 代理来源与出口策略（v1.6，融合 ProxyCat）

### 三种代理来源

设置 →「代理来源」里切换，**改完即时生效**，不重启：

| 来源 | 行为 |
|---|---|
| 内置池 `pool` | 只用本机抓取 / 手动添加 / 订阅导入的代理（默认） |
| API 接口 `api` | 定时（默认 5 分钟）向接口地址取代理列表，只取前 N 条；池空时收到请求会立即拉一次（60 秒节流），即「收到请求才取代理」 |
| 远程代理池 `remote` | 定时拉远程订阅地址（可以是另一台 ProxyDog 的 `/api/export?format=txt&token=…`） |

外部来源拉到的条目会打上 `api` / `remote` 标记：选外部来源时**只有该来源的代理参与轮换**，
切回内置池立刻恢复；入库后同样走归属地补全与验证。

### 失败占比淘汰

不再只看「连续失败几次」：每个出口维护最近 N 次结果的滑动窗口（默认 20 次），
**失败占比超过阈值（默认 60%）就隔离冷却**。一次网络抖动不会误杀出口，
真正时好时坏的坏出口会被及时清出去。开关与窗口/阈值都在设置 →「验证」里。

### 目标绕过名单

设置里填逗号或空格分隔的域名 / IP / 关键词（如 `.gov.cn, 192.168., bank`），
**命中的目标强制本机直连**、不占用任何出口，与当前轮换模式无关，任何时候都生效。

### 三档验证强度

| 档位 | 验证内容 |
|---|---|
| 快速 `fast` | 只测 HTTP 连通与状态码，最省时间 |
| 标准 `standard` | HTTP + HTTPS 探测，按设置决定是否验匿名，校验特征字符串 |
| 严格 `strict` | 再加匿名强校验：必须能被识别为高匿，且响应包含特征串 |

三档同时作用于「验证」「自动重验证」「场景模式」三处，避免不同入口口径不一致。

## 切换模式（v1.5.3 起，模式名与交互照无影）

| 界面选项 | 内部值 | 行为 |
|---|---|---|
| 轮询代理模式 | `round_robin` | 抽取高可用代理，代理无效时自动切换下一个；默认「延迟优先」只在最快的一批里挑 |
| 根据次数更换 | `by_count` | 每个代理IP使用设定的次数后切换下一个 |
| 根据时间切换 | `by_time` | 设置每隔几分钟更换一次代理（顶栏按分钟填） |
| 根据场景切换 | `scenario` | 配置验证网站后，每 2 分钟验证一次池子，验证失败时切换下个代理 |
| 根据关键词 | `keyword` | 黑名单：目标命中关键词时不走代理；白名单：只有命中才走代理；可限定目标站点 |
| 固定代理 | `exclusive` | 每次固定使用延时最短的代理地址，不切换；也可「手工切换」固定某条 |
| 粘性会话 | `sticky` | 同一客户端访问同一站点在 TTL 内固定同一个出口，保登录态、防风控；HTTP 还可用请求头 `X-Proxy-Session: 名字` 指定会话 |

**切换方式**：顶栏「模式」下拉直接选（照无影），旁边的 ? 气泡有全部模式的说明；
参数内联在模式旁边改——次数显示「设置次数 N 次切换」、时间显示「设置时间 N 分钟切换」、
关键词是「设置关键词」弹窗（黑/白名单单选 + 目标站点 + 关键词，保存/取消）、
固定代理显示「使用延时最短的代理」+「手工切换」按钮。顶栏还有「失效自动切换」开关和
「无限模式开/关」胶囊。切换即时生效，不需要重启，后端会同时重置轮换计数。

### v1.3 出口质量引擎

- **失败隔离**：转发失败不再直接判死（客户端断开、目标超时都会算失败），
  连续失败 N 次（默认 4）进入冷却隔离，到期自动复活；主动验证失败仍按原规则置失效。
- **健康度加权**：权重 = 延迟因子 × 历史成功率，可开关（设置里）。
- **延迟优先**（v1.5 默认开）：每次只在「最快出口延迟 + 窗口毫秒」且不超过池子前 25% 的节点里挑，
  既优先用最快的出口，又不会把同一条最快节点反复打爆；窗口大小可在设置里调。
- **无限模式**（顶栏开关，学无影）：开启后按延迟从低到高依次轮流、循环往复用遍全池；
  代理失效后不隔离、不因超延迟判死，等下个循环还会被调用；池内没有可用代理时，
  自动把失效/隔离的全部捞回来重新轮询，依此无限循环。关闭后恢复隔离与延迟上限判死。
- **出口去重**：同一 (IP, 协议) 多端口只保留最快一条，免费池同机开一排端口很常见。
- **单出口并发上限**：超过上限自动换下一个，防止把一条代理打爆。
- **客户端结果上报**：`POST /api/pool/report`（body: `{"id":123,"ok":false,"ms":900}` 或用 host/port/protocol 定位）。
- **Prometheus 指标**：`GET /metrics`（免认证，只含聚合数字，不含代理 IP）。
- **API Key 每日配额**：创建 Key 时可设 daily_quota，对 `/api/pool/*` 计费，超出返回 429。
- **IP 白名单**：设置里可填精确 IP 或 CIDR（逗号分隔），本机回环始终放行。
- 概览页可见轮换状态：当前出口、已用次数/时长、距下次轮换、粘性会话数、模式退化提示；
  代理池列表里隔离中的出口显示「冷却 Ns」。

### v1.5 实用功能补齐

- **失败自动重试**：出口拨不上/回 403 502 时自动换下一个出口再试（默认 2 次，
  设置里可调），坏代理不再把错误丢给你的程序——商业轮换代理的标准行为。
- **订阅输出**：`/sub/<token>?format=base64|txt|clash&protocol=&https=&limit=`，
  把池内有效代理变成订阅链接，SwitchyOmega / v2rayN / Clash 定时拉取自动同步；
  代理池页「导出」弹窗一键复制，可按协议、是否支持 HTTPS 过滤。
- **匿名度与 HTTPS 检测**：验证时顺带判定 elite / anonymous / transparent
  （按 X-Forwarded-For / Via 等代理头），并测出能否 CONNECT 443；代理池页新增
  「匿名/HTTPS」列，概览显示高匿/HTTPS 数量；设置里可关（关了验证更快）。
- **地区偏好**：设置里填 `US,DE,HK`，命中地区的出口被选中概率 ×4（geo targeting）。
- **延迟上限**：设置里选一档（默认 3 s）。验证通过但超过上限的出口直接判为
  不可用，并在验证结束时删除——它们不会进候选池、不会出现在订阅里，也不会
  继续占用轮换和验证时间；代理池页可以再按 ≤500ms / ≤1s / ≤2s / ≤3s 临时筛。
- **单条即时测试**：代理池页「验证」按钮改走即时测试接口，toast 直接返回
  延迟 / 匿名级别 / 是否支持 HTTPS。
- **顶栏模式快捷菜单**：点「模式：轮流」直接在按钮下方弹出六个模式单列菜单，
  点哪个切哪个，不用再进居中弹窗。

### GitHub 上怎么找免费节点

| 步骤 | 做法 |
|---|---|
| 去哪找 | 在 GitHub 搜 `proxy list`、`free proxy list`、`socks5 proxy list`，按 **Recently updated** 排序；star 多且今天还有提交的仓库才有活节点 |

| 怎么填 | 整仓抓：`owner/repo`；只要某个目录：`owner/repo/tree/分支/目录`。粘贴完整 github.com 链接也认 |
| 判断好坏 | 添加后点「测试」，试抓结果里能解析出 `ip:port` 就说明路径对；再点「立即抓取」正式入库并验证 |

面板里已预置 5 个实测可达的仓库（`officialputuid/KangProxy`、`databay-labs/free-proxy-list`、
`proxyscrape/free-proxy-list`、`sunny9577/proxy-scraper`、`mishakorzik/Free-Proxy`），
点 chip 即添加，不必手填。

| 类型 | key 位置 | 说明 |
|---|---|---|
| **FOFA** | 卡片「接入」→ key（老账号再补 email） | 查询语法默认 `protocol="http" && (header="Proxy-Agent" \|\| body="Proxy")`；免费账号每次 100 条 |
| **鹰图 Hunter** | 卡片「接入」→ key | 每页 20 条消耗积分，时间窗口默认最近 30 天 |
| **Quake 360** | 卡片「接入」→ key | 单次最多 500 条 |
| **Shodan** | 卡片「接入」→ key | 免费账号每月仅 100 条结果 |
| **ZoomEye** | 卡片「接入」→ key | 用 API-KEY 请求头认证 |
| **GitHub 仓库** | 无需 key | 填 `owner/repo` 即可，自动发现 http.txt / socks5.txt / proxies.json 等清单（走 jsDelivr，国内直连、不耗 GitHub 配额）；支持 `owner/repo/tree/分支/子目录` |
| **自定义清单地址** | 无需 key | 任意 http(s) 直链，纯文本 / base64 / Clash YAML / JSON 都吃 |

要点：

- **协议选 `auto`**：同一地址同时按 http + socks5 两条入库，让真实请求验证去判定，
  适合"混合协议总表"类仓库（老的 sunny9577 限制就是这样解掉的）
- 仓库路径能判断协议时（如 `/socks5/` 目录）按路径走，不凭空翻倍；socks4 文件自动跳过
- **测试按钮**：试抓前 20 条但不入库，用来验证 key、查询语句、仓库地址是否有效
- **填完 key 先点「测试」**：能返回候选地址说明 key 与语法都对；报 `401/403` 是 key 无效或没权限，
  报「余额不足 / 积分」是额度用完，报语法错就回官网控制台复制一条能正常搜索的语句
- 空间测绘源只有在「总开关：开」且该源「启用」时才参与定时抓取；配置好后点「立即抓取」跑一次
- 同一个仓库 / 同一条查询语句不允许重复添加
- 凭证只存本地数据库，面板上永远显示掩码（`ab****cdef`），编辑时留空即保持原值
- 「总开关」一键暂停全部自定义源，不动配置

空间测绘的现实预期：返回的是"疑似在跑代理的 IP:端口"，**有效率通常只有个位数百分比**，
所有结果都会先过一次真实请求验证。想提高命中率，查询语句带上代理特征
（`Proxy-Agent`、`Proxy-Authenticate`）比裸搜 `port:8080` 强得多。

预置的推荐仓库（面板上一键添加，均已实测可达）：
`officialputuid/KangProxy`、`databay-labs/free-proxy-list`（按国家分目录）、
`proxyscrape/free-proxy-list`、`sunny9577/proxy-scraper`、`mishakorzik/Free-Proxy`。

`https://` 出口的验证走单独一条路径（TLS 连代理 + CONNECT 看 2xx）：aiohttp 的 `proxy=`
只认 `http://`，用默认逻辑会把 https 出口全判成不可用。

## 归属地：本地离线库，自动补全

归属地**不走任何在线接口**。第一次使用时点「地区库」下载一次离线数据（推荐城市级，
约 35 MB，下载后自动转成 5 MB 左右的本地索引），之后：

- 新代理入库、验证完成后**自动**补上归属地，不用手点；
- 服务启动时后台每 60 秒扫一次，把漏掉的补齐；
- 查询是纯本地二分（几万次/秒），地区列、地区分布、地区偏好全部实时可用；
- 国内 IP 精确到「省-市」（如 中国-江苏省-南京市），国外到「国家-州/省-市」；
- 「下载国家级（约 11 MB）」是轻量替代，只到国家。

内网 / 保留地址直接本地判定（局域网 / 本机 / 保留地址），不占库。

## 订阅支持范围

- 纯文本：`ip:port`、`ip:port:国家`、`http://u:p@ip:port`、`[IPv6]:port`
- base64 包裹的上述文本
- Clash / Mihomo `proxies:` 段里的 `http` / `https` / `socks5` 节点
- JSON 数组：字符串或 `{ip,port,protocol}` 对象

**不支持** `ss://`、`vmess://`、`trojan://` —— 它们不是 HTTP/SOCKS5 上游，
无法直接作为本工具的出口，导入时会跳过（启动日志里能看到解析数量）。

## 注意

- 免费代理可用率通常 10%~20%，别用来登录账号、过验证码或支付。
- 默认只监听本机。如果改 `listen_host` 为 `0.0.0.0`，请同时开启入站认证，
  否则同一网段的人可以拿它当跳板（面板顶部会持续显示告警）。
- 验证默认打 `https://www.baidu.com`，可在设置里改；超时 8s、并发 80，
  家用网络下建议不要超过 150。
- 抓取单次上限默认 2000 条（`max_fetch_total`），全量验证很慢，够用即可。
- GeoNode 接口默认关闭（`fetch_geonode=false`），需要时在「设置 → 抓取」里勾上。
- 访问日志默认保留 7 天（`access_log_days`），后台每天自动清理；数据库每天自动备份到 `data/backups/`。
